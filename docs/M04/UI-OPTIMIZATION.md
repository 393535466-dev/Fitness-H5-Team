# M04 训练体验优化与二级页面 · 2026-10-21

## 本轮确认

用户已确认：先完善课程、模板计划、计时记录和提醒；逐动作、组数、次数、重量不在本轮新增范围。先交页面，正式课程介绍、准备清单、动作要点和视频后补。

依据《Keep 与训记训练板块竞品拆解报告》（2026-10-21）的设计建议实施，不将其未验证功能当作竞品事实。继续沿用既有 QY-MYSQL-1.0.0 规则，不改公共类型、数据库、根依赖、其他组页面。

## 保留与取舍

- 保留团队原浅紫视觉、主导航和 M04 的真实 API 注入方式。
- 从 Keep 的课程组织思路借鉴“先了解，再开始”；从训记/Hevy 借鉴“保留用户意图与实际结果”的原则，不引入本期未支持的逐组记录。
- 首页集中到今日行动：未安排、已有今日课程、休息日、正在训练四种状态。今日安排与正在查看的日历周分开读取，切换周不改变今日课程判断。
- 将原弹层拆为页面，支持可复制 URL、浏览器前进后退和底部主导航返回。模块仍挂载在 `/training`，用查询参数区分页面，避免影响共享导航。
- 计划不再默认从当周周一开始；默认今天，可选开始日期，预览每一天的训练与休息。提交前明确旧 active 计划如有将归档，训练成果保留。现有查询接口只能读指定周，不能据“本周无计划”断言全局不存在 active 计划，因此新建也说明替换语义。
- 计时页以活动时间和课程目标为主，奖励细则放在可展开说明中；完成保存和放弃分开，放弃有明确二次确认。
- 课程说明与学习页共用真实 CourseDto。看说明、看视频不自动开始或完成训练。训练中进入学习页保持原会话，页面显示“仍在计时/已暂停”；暂停仍由用户主动控制。
- 提醒区分未设置、设置已保存、已关闭以及有未保存修改。浏览器/App 推送未接入时不可新增选择；允许取消历史配置中已失效的通道。保存成功不展示“推送已送达”。
- 成果、奖励资格、实际积分和估算消耗分别表达；保留未达门槛的已完成记录。汇总刷新失败不把已经保存的业务结果改写为保存失败。
- 正式教学内容缺失时明确标注，不补造动作库、学习进度、AI 处方、动作正确率或训练效果提升数据。

## 页面与主要交互

| 页面 | 预览地址 | 核心内容 |
| --- | --- | --- |
| 运动首页 | `/training` | 今日行动、计划入口、周日历、课程筛选、今日成果与记录 |
| 计划列表 | `/training?view=plans` | 模板描述、训练/休息天数、进入预览 |
| 计划预览 | `/training?view=plan&id={templateId}` | 逐日日程、关联课程、开始日期、替换前确认 |
| 课程详情 | `/training?view=course&id={courseId}` | 课程类型/难度/时长/估算消耗、介绍、学习入口、开始计时 |
| 课程学习 | `/training?view=learn&id={courseId}` | 正文、可用视频、缺省内容、返回详情或同一训练 |
| 我的训练 | `/training?view=session` | 恢复训练、活动时间、暂停/继续、完成保存、放弃确认 |
| 本次成果 | `/training?view=result` | 刚刚结算的训练成果与实际奖励；刷新后无本次对象时引导查记录 |
| 训练记录 | `/training?view=records&date=YYYY-MM-DD` | 上海日期筛选、前一天/今天快捷切换、分页、不同状态和奖励说明 |
| 训练提醒 | `/training?view=reminder` | 保存状态、时间/星期/通道/跳过规则、未保存提示与校验 |

计划进入课程会保留 `from=plan&templateId=...`；训练进入学习保留 `from=session`，返回时不创建另一份训练。课程 ID 编码后交给模块适配器，后端仍按原契约校验 UUID。

## 内容补齐与联调边界

未修改后端状态机、80% 开发奖励阈值、同日同课程去重、服务端计时或通知 Worker。真实登录/数据库/积分/媒体/推送仍按 HANDOFF 联调，页面设计完成不代表服务已上线。预览只在显式 `NEXT_PUBLIC_M04_PREVIEW=true` 开发模式启用，内存数据会在刷新或开发热更新时重置。
