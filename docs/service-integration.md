# 真实服务接入清单

首版采用单机演示实现，未配置密钥、数据库、账号或云服务。

| 功能 | 当前实现位置 | 后续接入 |
| --- | --- | --- |
| 饮食识别 | src/lib/health/services.ts 的 demoRecognize | 服务端接收图片、模型识别、返回候选及置信信息，保持用户确认步骤；密钥只在服务端 |
| 陪伴聊天 | src/lib/health/services.ts 的 demoReply | 服务端模型接口、消息历史、流式响应及异常恢复；完善情绪支持边界 |
| 商家地图 | src/lib/health/seed.ts 的 restaurants | 明确申请定位授权、地图商家 API、真实位置、距离与来源 |
| 训练与通知 | src/features/training/training.tsx | 真实课程内容、计时恢复；H5 通知需要平台支持与用户授权，App 使用原生通知 |
| 预约与社交 | src/lib/health/reducer.ts 的 book/cancel | 后端幂等预约、容量校验、取消规则、服务端日期、身份权限和消息通知 |
| 积分 | src/lib/health/reducer.ts 的 ledger | 服务端原子流水、防重复奖励、兑换履约；客户端余额不能作为真实权益依据 |
| 健康档案与记录 | src/components/health-provider.tsx | 登录、数据库、跨设备同步、存储迁移与隐私控制 |

## 可复用边界

`types.ts` 定义数据对象，`reducer.ts` 定义本地交互规则。后续逐步将持久化与外部服务替换为接口实现，保留页面的显示与确认流程。未来原生 App 可以共享数据协议和业务规则；原生界面、摄像头权限、推送、定位与健康设备接入需要单独实施。

## 本地状态

首次渲染使用固定结构，挂载后读取版本化本地记录，读取完成前不写入。损坏或未知版本回退种子并提示；无法写入时保留本次会话内状态并说明刷新风险。所有即时记录在点击时解析 Asia/Shanghai 日期；历史体重表单仍记录用户选择的日期。积分任务与训练完成按日期去重，预约按活动 ID 去重。
